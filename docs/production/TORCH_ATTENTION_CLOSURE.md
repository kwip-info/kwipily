## Root decisions and explicit utility

Adopt the preflight's dense observation-first float32 CPU/MPS contract, configuration ranges, exact native parameter ownership, checked allocation/work ceilings and portable export. Fixed batch_first; equal SDPA head counts; no grouped-query, nested/sparse/ragged/autocast, implicit KV cache or MPS exact continuation. CPU exact continuation and explicit MPS weights-only restarts use existing supervision.

Masks use int64 binary values, **1 blocked /0 allowed** everywhere in graph/UI. Invert only at the SDPA native boundary. Combined attention/padding masks must leave an eligible source for every query; fully blocked rows are refused before native score allocation. Native extra key/value positions follow the native unblocked augmentation contract; do not use them to make an otherwise invalid fully blocked original source silently pass. Supplied masks and causal mode are mutually exclusive. Causal masks are square; unequal-length causal hints are refused explicitly.

Include one uncredited `attention_mask` utility so supplied mask ports work on the actual universal canvas. It receives required `query` and `key` floating reference connections with the same positive observation count/device. Both must be rank3[N,L,E]/[N,S,K] or both rank4[N,H,L,D]/[N,H,S,Dk]; observation-first shape metadata derives L/S (no value-to-index reinterpretation). Configuration-v1 fields: `mode` none/causal/blocked(default none), `blocked_queries` ordered integer list(default[]), `blocked_keys` ordered integer list(default[]), `padding_keys` integer list(default[]). Paired blocked lists must have equal count; coordinates nonnegative/in-bounds and unique pairs. Padding indices nonnegative/in-bounds/unique. Nonempty paired lists require blocked mode; causal requires L=S; none/causal reject paired lists rather than ignore them. Bounds match the connected resolved reference geometry. This utility always exposes `mask` int64[N,L,S] (blocked/causal connections union padding columns) and `padding` int64[N,S] (padding alone). Binary union, not additive duplication, applies; this makes padding usable by SDPA’s single mask port. its configured blocked connections/padding apply explicitly to every observation. It owns no learned state and has no gradients; downstream attention retains ordinary floating input gradients. References remain finite dense float32; masks are generated on their device. Mask elements and work obey the100M ceiling before allocation. Source-derived arbitrary per-observation dynamic masks remain a future data-source extension, explicitly documented. Dedicated lesson trusted mask fixtures do not imply generic production mask sources.

Configuration schemas, conditional supplied ports, mask builder, native adapter, export and lessons must agree. Public picker names explain comparison groups (heads), blocked connections, sequence positions and query/key/value before technical terms. Named weights are real output tensors, never parameters or fabricated SDPA output. Shared presentation validator must explicitly validate all MHA named roles (including unconnected weights) using source geometry/configuration/capture policy; single-output operators retain common strict validation.

## Shared detailed specification

The following preflight sections define the agreed detailed controls, ownership, resource model, reusable seams and independent references, as amended by the root decisions above.

## Shape and mask contract

Dense float32 CPU/MPS only; no sparse, ragged, nested, unbatched or autocast cases. Batch/observation is always first. Module batch_first=True is fixed, not a UI toggle. Attention never carries hidden state across calls and has no implicit KV cache. All connected operands must share positive observation count/device. Inference is eval, not simply no_grad.

| Component | Floating input ports | Output ports/shapes |
| --- | --- | --- |
| MHA | query[N,L,E], key[N,S,K], value[N,S,V] | out[N,L,E]; optional weights[N,H,L,S+extra] or averaged[N,L,S+extra] |
| Transformer | source[N,S,E], target[N,T,E] | out[N,T,E] |
| Encoder | in[N,S,E] | out[N,S,E] |
| Decoder | target[N,T,E], memory[N,S,E] | out[N,T,E] |
| SDPA | query[N,H,L,D], key[N,H,S,D], value[N,H,S,Dv] | out[N,H,L,Dv] |

Named MHA weights are display/inspection output, not extra learned parameters. `extra` is add_bias_kv plus add_zero_attn if those controls are included. If returning weights is disabled, its port is unavailable, not a None tensor. Average-weights changes rank and must update inference/ports/preview/export. SDPA exposes only the native result; do not invent a returned-weight API. Different source/query lengths are supported; SDPA grouped-query attention is initially explicitly refused (enable_gqa=false). No change to the reviewed four modes. On the installed MPS runtime, positive-dropout SDPA training with fixed inputs refuses in the fused native dispatcher. The reviewed wrapper and portable export use a device-local public Torch matmul → masked softmax → F.dropout → matmul path only for MPS positive-dropout training, with identical mask/scale/finite/resource admission. No CPU fallback, private primitive or artificial gradient leaves. Exact discovery declares sdpaMPSDropoutExecution=deviceLocalPublicOps for SDPA and notApplicable for the other five. Evaluation and zero dropout retain functional SDPA.

Use **1 means blocked, 0 means allowed** throughout graph/UI, irrespective of native API. Represent supplied masks as dense int64 with exact binary values, no gradients, no arbitrary float -inf authored data. Convert to native bool at the adapter boundary; invert only for SDPA. No broadcasting between observations or heads hidden from the learner. Proposed per-observation attention masks[N,L,S] replicate over H internally where native MHA requires[N×H,L,S]; SDPA gets[N,1,L,S]. Padding masks[N,S] are optional separate ports. Validate binary values, bounds and combined mask rows before native execution. Every query must retain at least one eligible key after attention/padding combination. Preserve the same refusal in export. Causal mode generates the blocked upper triangle; explicit supplied mask and causal mode are mutually exclusive. Square causal self-attention is the initial causal bound; refuse non-square causal/cross-memory hints with actionable guidance rather than silently relying on native alignment/hint interpretation.

MHA mask controls: attention_mask_mode none/causal/supplied and padding_mask_mode none/supplied. Transformer: source_mask_mode, target_mask_mode, memory_mask_mode (none/supplied for memory), plus source/target/memory_padding modes; ports conditional on supplied. Encoder: mask_mode and padding mode. Decoder: target/memory masks and padding modes. SDPA: mask_mode none/causal/supplied, no separate padding port (combine through mask construction).

## Mask-source seam (decision frozen above)

ContractDType already supports bool/int64; typed output addresses, integer index sources and multi-input DAGs exist. But production GraphValidator permits exactly one primary Input, and engine input/index_input both consume the same x. A normal floating source cannot independently supply int64 masks. Merely declaring mask ports would make production mask workflows inaccessible; do not reinterpret floating x as an index source or loosen that source contract.

Choose a bounded explicit solution before coding:

1. Recommended utility: an attention mask builder with query/source reference ports, configured blocked position lists and optional causal recipe, emitting binary int64[N,L,S] and/or padding[N,S]. It derives geometry/N from connected floating references, not independent sample data. Existing integer-list controls can edit blocked coordinates/positions, with the shape shown in Information. It adds no reviewed capability credit. This makes supplied mask ports genuinely usable from the universal canvas and supports each example without a new multi-source data architecture.
2. Smaller alternative: configuration-generated causal/blocked-position masks inside the attention node, initially no supplied ports. This honestly supports useful masks but postpones generic mask wiring; root must explicitly approve that scope rather than imply supplied-mask support.

Dynamic per-observation masks from arbitrary data need a later source/binding contract if neither solution supports them. Utility masks have no gradients; lessons can use trusted int64 fixture sources under their dedicated namespace without implying generic production sources exist.

## Configurable fields and ownership

Common module controls: model width E1..512 (default4), heads1..32 (default2), E divisible by heads, dropout0..1 (default0), bias Bool. Transformer/Encoder/Decoder: feedforward width1..4096(default8), layer counts1..8(default1; separate encoder/decoder counts for Transformer), activation relu/gelu, normalization safety value positive finite float32(default1e-5), norm_first Bool, and optional final normalization for standalone Encoder/Decoder. Standard Transformer owns its native final norms; no custom encoder/decoder or arbitrary callable activation. Constructor-owned final LayerNorm must follow the declared epsilon/bias, not silent library defaults.

MHA: embed_dim, heads, dropout, bias; key/value width equal/custom with positive integer width; add_bias_kv and add_zero_attn Bool; return_weights Bool and average_weights Bool; mask modes above. Unequal K/V produces native q_proj_weight/k_proj_weight/v_proj_weight rather than in_proj_weight; bind actual native names/shapes, not a fixed flattened weight bank. Additional learned key/value biases are native-owned when enabled; added zero attention is not learned. If root excludes these two optional native augmentation controls, document refusal explicitly and retain non-default K/V, bias/head/mask coverage.

SDPA: dropout, scale_mode automatic/custom (custom positive finite scale), mask mode. Fixed equal head counts, equal query/key last width, independent positive value width. No learned parameters/buffers; use a small owning nn.Module solely for training/eval/dropout/state lifecycle. Native functional SDPA always applies configured dropout irrespective of eval: wrapper/export must pass p only when self.training, otherwise0. No dummy parameter to manufacture optimizer/state credit.

Native parameter ownership is already representable through engine named_parameters/state_dict and checkpoint shape/name checks. Transformer stores encoder.layers.*, decoder.layers.*, native self_attn/multihead_attn projections, feedforward layers and norms. Encoder/Decoder clone the prototype layer, so native initialization gives equal initial values across cloned layers while each remains a separate parameter. Preserve native behavior and disclose it; do not silently randomize clones as a hidden application initialization policy. Transformer performs its own native Xavier reset. Exact names/shapes/counts must be generated from reviewed constructor formulas and cross-checked independently against installed native modules before allocation.

## Device, resource and export boundaries

Use strict preallocation checked arithmetic: learned parameters≤2million, all outputs≤100million elements, attention score storage≤100million, conservative work≤100million. Include N×H×L×S across every layer/attention sublayer, returned weights and augmented source positions; QK and AV work scales with (D+Dv), and module projections/feedforward multiply widths. Encoder adds each self-attention/feedforward; Decoder adds self plus cross attention; Transformer adds both stacks. Shape admission per observation, actual execution/export rechecks N. Masks add their own bounded elements. Return-weights allocation must be counted even if unconnected. No trust in declared output shapes; all roles finite-validated after execution.

CPU/MPS supported under the probed dense subset, without silent fallback. CUDA-only kernel selection is not a setting for this Mac product. Disable nested-tensor optimization; avoid native causal hints unless explicit masks agree. Dropout-active modules join existing stochastic-node metadata. Exact CPU continuation restores module + optimizer + scheduler + RNG and preserves train/eval; MPS remains weights-only. SDPA state-roundtrip verifies canonical config/mode/empty owned state, checkpoint identity and CPU RNG when dropout is active; changed recipe/input shape cannot masquerade as compatible state.

Portable export must reproduce constructor controls, masked shape/value/budget admission, fixed batch-first semantics, native ownership and named MHA outputs. Use ordinary torch modules/functional APIs plus the reviewed small pure helpers, never require KwipML imports. Actual standalone subprocess tests must load real weights and compare outputs/gradients/eval/dropout continuation. Empty SDPA state loading must reject unexpected keys. The regular classifier head provides trainable parameters in a genuine SDPA example, without attributing those weights to SDPA.
