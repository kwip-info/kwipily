## Canvas recipe and compatibility

Proposed stable component IDs: `optimizer_sgd`, `optimizer_adam`, `optimizer_adamw`, `optimizer_rmsprop`, `optimizer_adagrad`. These are training control components, not tensor-producing model layers. Each outputs one typed optimizer recipe through `out`; Train gains an optional single `optimizer` recipe input. They have no model-forward/input-gradient execution, no tensor dimensions, and no persistent optimizer instance in a canvas node. Runtime creates one fresh optimizer per admitted training job. Connection validity, configuration and recipe identity are shared contracts rather than component-specific UI hacks.

An unconnected Train preserves the exact historical Adam recipe and Run Setup learning rate, old graph bytes, legacy codec admission, historical checkpoint-contract representation and provenance. An explicitly connected recipe owns its learning rate; Run Setup's rate remains saved but is visibly inactive for that Train. Effective configuration and its source node appear in run preparation, History and exported training settings. Disconnected optimizer nodes have no effect on a selected run. Reject multiple recipes, wrong port types and unsupported versions before archive capture. Existing files must not acquire explicit optimizer nodes merely by opening or saving.

Introduce a narrow new workflow-schema feature boundary for optimizer nodes/Train input and a versioned optional prepared-run optimizer payload. Preserve old supported schemas and strict unknown-field rejection. Do not silently admit new features in old schemas or broaden model primitive validation. Graph compiler resolves exactly one selected recipe; runtime verifies it independently. Missing new descriptor must refuse explicit recipes even when the legacy Adam path is available. Dedicated per-ID optional descriptor discovery, palette counts, stale/revoked support and queued-run revalidation follow existing accepted families.

Experiment overrides target the effective rate: existing `learningRate` overrides continue for implicit legacy Adam. Explicit recipes use a declared optimizer-configuration override path, such as `optimizer.lr`, and report its source. Refuse a legacy-rate override for an explicit optimizer with an actionable instruction; never ignore it. Root must freeze the exact transport/path spelling before implementation. No new experiment engine or optimizer comparison dashboard is required.

## Supported controls and numeric bounds

Controls use installed Torch 2.14.1 defaults and shared inspector templates. Numeric values must be finite, actual numbers rather than booleans; no tensor-valued hyperparameters, arbitrary dictionaries or unknown fields. Canonical missing fields receive defaults. Proposed common nonnegative float32-safe scalar range is 0 through 3.4028234663852886e38, with execution refusing nonfinite results/state. Epsilon is positive normal-float32 range 1.1754943508222875e-38 through 3.4028234663852886e38. Rate zero is supported and taught as a no-update baseline. Fractions marked below are bounded separately. These are bounded consumer contracts, not blanket upstream API equivalence.

| Component | Fields and defaults | Additional constraints |
| --- | --- | --- |
| SGD | `lr` 0.001; `momentum` 0; `dampening` 0; `weight_decay` 0; `nesterov` false; `maximize` false | Momentum and dampening [0,1]. Nesterov requires momentum >0 and dampening =0. |
| Adam | `lr` 0.001; `beta1` 0.9; `beta2` 0.999; `eps` 1e-8; `weight_decay` 0; `amsgrad` false; `decoupled_weight_decay` false; `maximize` false | Each beta [0,0.9999999403953552], explicitly below one. |
| AdamW | `lr` 0.001; `beta1` 0.9; `beta2` 0.999; `eps` 1e-8; `weight_decay` 0.01; `amsgrad` false; `maximize` false | Same beta bounds; decay is always decoupled, no redundant editable switch. |
| RMSprop | `lr` 0.01; `alpha` 0.99; `eps` 1e-8; `weight_decay` 0; `momentum` 0; `centered` false; `maximize` false | Alpha and momentum [0,1]. |
| Adagrad | `lr` 0.01; `lr_decay` 0; `weight_decay` 0; `initial_accumulator_value` 0; `eps` 1e-10; `maximize` false | Decay and initial accumulator use the common nonnegative range. |

Pin `foreach=False`, `differentiable=False` and, where constructors expose them, `fused=False` and `capturable=False`. Do not present unavailable flags as configurable capabilities. Dense float32 trainable parameters on CPU/MPS only; retain existing model/resource limits. No sparse gradients, parameter-group editor, tensor rates/betas, optimizer-through-optimizer differentiation or automatic backend fallback. Parameterless model components can coexist, but an empty selected trainable parameter set refuses training. Maximize is an explicit advanced objective direction, not a promise of improving classification accuracy.

Inspector labels introduce concepts plainly: Learning rate, Momentum, Momentum dampening, Weight decay, Look ahead, First/Second running average, Stability amount, Keep largest squared average, Separate weight decay, Squared-average memory, Center the squared average, Learning-rate decay and Starting accumulated squares. Information defines terms with a small step table. Inactive controls retain unapplied/saved values; shared Apply/Discard semantics remain intact. No required code or hidden settings.

## Parameter ownership and strict state

One declared parameter group contains each selected, trainable learned parameter exactly once in deterministic model order. Preserve frozen parameters, shared parameter identity and parameter/buffer separation. Buffers are never optimizer-owned. Capture canonical configuration, ordered parameter identities/shapes/dtypes and effective optimizer implementation/version in provenance; do not serialize Python objects or arbitrary callables.

Strict operator-specific state keys after updates:

| Optimizer | Per-parameter state |
| --- | --- |
| SGD | Empty without momentum; otherwise `momentum_buffer`. No fabricated step counter. |
| Adam / AdamW | `step`, `exp_avg`, `exp_avg_sq`; add `max_exp_avg_sq` iff AMSGrad. |
| RMSprop | `step`, `square_avg`; add `momentum_buffer` iff momentum >0 and `grad_avg` iff centered. |
| Adagrad | `step`, `sum`, including its real initialized accumulator before the first update. |

Validate exact keys, one group/order, canonical hyperparameters, tensor shape/dtype, finite values and scalar counter identity. Counters are observed CPU scalar float32 tensors with the pinned implementations, including MPS optimizers; do not cast them into model weights. Squared averages/accumulators are nonnegative; AMSGrad maximum must dominate its squared average within justified float tolerance. A parameter with no gradient must not be awarded an invented update or initialized state. Expected counter values follow actual per-parameter updates, not an assumption that every tensor received every batch. The initially materialized Adagrad state and uninitialized lazy state of other optimizers need separate valid cases. Reject missing/extra/foreign state, duplicate parameters, altered options and nonfinite moments before restoring anything.

CPU epoch-boundary exact resume must reproduce uninterrupted parameters, optimizer state, model buffers, RNG and metrics for all five. Existing legacy Adam checkpoint signatures and restores stay byte/semantically compatible. New explicit recipes record a versioned optimizer contract; no broad acceptance of arbitrary state dictionaries. MPS remains weights-only fine-tuning: restore validated model parameters and buffers, then create fresh optimizer state and reset epochs/RNG as the existing lifecycle declares. Refuse exact MPS resume honestly. Changing optimizer/options is allowed only through explicit fresh fine-tuning/new training, not exact resume. Cancellation and failed steps cannot publish a completed or corrupt checkpoint.

## Export and scheduler seam

Portable inference exports remain model-only and do not execute optimizer components. A clean training-recipe export exposes the actual selected optimizer and canonical constructor arguments, resolved learning rate and trainable parameter selection; generated code uses real constructors and supports a fresh training step. Exported checkpoint metadata identifies the optimizer and supported continuation policy without claiming portable exact resume on arbitrary machines. Independent exported training-step checks compare saved initial parameter/gradient inputs and scalar reference updates, rather than comparing the adapter to itself.

The prepared recipe reserves an optional versioned scheduler seam, currently absent. There is no scheduler node, scheduler state or dynamic learning-rate behavior in this batch, aside from Adagrad's own `lr_decay`. Its semantics remain distinct from future scheduler progression. Future scheduler ownership must attach to the admitted optimizer, preserve precedence and checkpoint ordering, and cannot change accepted optimizer defaults.
