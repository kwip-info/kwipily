# PyTorch v1 consumer capability scope review — 2026-10-08

Status: **88-unit scope approved by owner on2026-10-08**. The owner approved the reviewed list via explicit reply. Catalog0.2.0 migration is implemented and accounting-verified; evidence reconciliation remains separate; this changes no runtime or release acceptance. The owner selected a reviewed user-facing capability list as the denominator for the 90% target. This document makes that list concrete; it does not claim coverage of 90% of the complete PyTorch API.

## Evidence inspected and counting rule

The proposed [selection](../../capabilities/selection-v1.json) contains 99 canonical entries across 17 families. The [catalog](../../capabilities/catalogs/v1/pytorch.json) now records the approved88-unit consumer denominator, with pending per-unit mode/backend review and production evidence. Its 9,066 Sphinx objects include framework internals and are not a consumer denominator. Source inspection finds 29 model/boundary definitions in `Sources/KwipMLCore/Resources/components.json`, comprising 25 distinct selected operation candidates, three graph boundaries and a depthwise specialization of Conv2d. Current source/control presence does not establish evidence-complete production coverage.

The local runtime manifest `.local/runtime-canvas-current/runtime-manifest.json` records Python 3.13.6, PyTorch 2.14.1 and arm64; [post-ART review](POST_ART_COVERAGE_REVIEW.md) records the runtime context. This is a development candidate, not clean-machine, signed distribution or all-device acceptance. Docs version 2.14 is not proof of patch-level runtime parity. No builds or numerical tests were run by this audit.

A counted unit is a meaningful configurable consumer operation or lifecycle, presented by a node or explicit canvas-connected control. It requires declared modes, real execution, generated/exported behavior, persistence, actionable failures, example, concurrent lesson/assessment contract, generated icon where it is a component, and independent evidence plus native acceptance. An internal call or reserved lesson ID earns no unit. Supported dtype/rank/device limits must be visible and versioned. The project skill’s component-delivery instructions apply; repository contracts are [bundle ADR](../architecture/ADR-002-COMPONENT-BUNDLES.md), [component contract](../components/DESIGN_AND_CONTRACT.md) and [learning contract](LEARNING_CONTRACT.md).

## Recommended denominator: 88 units

Preserve every selected layer, tensor operation, attention, recurrence, loss, optimizer and scheduler. Consolidate only API storage/lifecycle/policy surfaces into meaningful product units:

| Family | Original entries | Reviewed units | Reason / compulsory modes |
|---|---:|---:|---|
| Composition | 4 | 1 | A configurable model architecture covers ordered/named, sequential/branched/nested structures. ModuleList/ModuleDict storage classes are not separate consumer features. |
| Data | 5 | 2 | Dataset source/view owns indexed/tensor/subset and iterable modes; batch loader is separate. Every promised source mode must ship. |
| Serialization | 3 | 2 | Save and restore form one complete lifecycle; executable program export remains separate. |
| Autodiff | 3 | 2 | Requested gradients and accumulated backward gradients are distinct required modes in one inspection unit; frozen no-gradient inference is separate. |
| Initialization | 4 | 1 | One selectable initialization policy must deliver all four named algorithms, not only one default. |
| Other twelve families | 80 | 80 | Keep all semantically distinct selected operations. |
| **Total** | **99** | **88** | Eleven duplicated consumer surfaces consolidated; no hard operation removed. |

90% requires **80 complete units** (ceiling of 79.2); 95% requires **84** (ceiling of 83.6). These percentages are for this approved product scope only. They are not current progress. At least one accepted unit per required family remains compulsory; propose an additional explicit release review of the at-most-eight deferred units so that attention, recurrent networks, losses, optimizers or schedules cannot disappear behind a high aggregate score. Owner must approve the final deferral list and mode boundaries before catalog freeze.

No split of one feature into aliases, dimensions, UI modes or internal methods can inflate the numerator. Conversely, a consolidated unit earns one credit only when every mode stated here is delivered or explicitly narrowed by a recorded pre-freeze scope decision. The 25 existing operation candidates represent 25/88 source mappings (28.4%), **not 28.4% production acceptance**. No complete-unit numerator is assigned by this audit.

## Partial controls: meaningful work before credit

- Architecture: existing model definition and file-backed Block are real starting features. Bind named/ordered interface, persistence/pinned revision, independent instance weights versus deliberate sharing, train/eval propagation and export into a declared architecture unit. A `GraphModel` subclass alone is insufficient. [File documents](FLOW_DOCUMENTS.md) and [separable recipe](TORCH_SEPARABLE_CONV2D.md) provide scoped starting evidence.
- Dataset and loader: prepared source/mapping/splits plus Run setup batch/seed are useful. Neither proves iterable sources, tensor subsets, drop-last/shuffle/collation or resumable loader ordering. Either implement declared modes or explicitly approve a narrower mode contract before freezing; never use fifteen wrangling components as fifteen PyTorch data units.
- Checkpoint save/restore: [lifecycle](../CHECKPOINT_LIFECYCLE.md), [continuation](../WORKFLOW_CHECKPOINT_CONTINUATION.md) and [trained export](../uat/WORKFLOW_TRAINED_EXPORT_NATIVE.md) cover meaningful controls. Rebind them with exact continuation versus fresh/fine-tune semantics, compatibility/refusal and safe load provenance. Generated Python and state files do not prove exported-program support.
- Autodiff/frozen: current assessed tasks, bounded gradient capture and frozen evaluation are useful evidence. A chosen visible gradient inspection target/mode and accumulated-state policy are required for the two-method unit. Ordinary internal `backward()`/`no_grad()` calls receive no independent credit.
- Loss/optimizer: the present binary classifier and fixed Adam are not selectable general objective/optimizer support. Eight distinct losses and six distinct optimizers remain in the denominator, including sequence alignment and LBFGS requirements. Initialization defaults are likewise not four shipped configurable algorithms.

## Explicit exclusions and semantic aliases

Exclude framework-private symbols, module hooks/internal storage/introspection methods, constructor aliases, tensor method spelling aliases, generated overload entries, automatic differentiation internals, compilation/distributed plumbing and upstream classes outside this selected product scope. Record exclusions in the eventual catalog rather than deleting the original inventory. Public APIs outside the reviewed list are **out of v1 selected scope**, not “covered.” This review makes no all-public-framework completeness claim.

`torch.cat` and a palette label “Concatenate” identify one unit; `torch.reshape` and `.reshape()` one unit if equivalent supported modes are tested. Depthwise Conv2d is grouped-convolution specialization; a separable recipe composes it with pointwise Conv2d and remains an example/architecture, not a new primitive. Sequential/ModuleList/ModuleDict are composition modes, not interchangeable semantics: ordering and naming still must be preserved. Grad/backward, save/load and initialization algorithms are consolidated required modes, **not semantic aliases**. No replacement of attention with matmul+softmax, recurrent cells with linear+tanh, or an optimizer/scheduler with a learning-rate field is permitted.
