This is a small initial set of seven deterministic evidence rules, not hundreds of expert diagnoses. `RunDiagnostics.evaluate(_:error:)` returns stable rule IDs, titles, quantified evidence and suggested next steps. It never modifies a graph, source, recipe or compute backend. UI interpretation and computer-use verification are owned by the root integration.

## Trend evidence contract

Metrics are real observations delivered to the application. For long runs they may be sampled for UI responsiveness; the export remains the complete measurement record. Diagnostics do not fabricate or interpolate missing epochs.

Non-finite observations are reported immediately and suppress all trend rules. Otherwise, only positive, distinct epoch records count; later duplicate records replace earlier ones for that epoch. Trend analysis uses the latest 20 distinct observed epochs and requires at least 10. It compares arithmetic means of the first five and last five observations in that window. Negative losses or out-of-range accuracy suppress trend conclusions. Findings disclose observation count, epoch span, and both actual loss means.

These thresholds are explicit initial product heuristics, not calibrated statistical tests. No confidence probability is reported. Absence of a finding does not establish model health.

| Stable ID | Trigger | Interpretation |
|---|---|---|
| `measurement.nonfinite.v1` | Any non-finite train loss, validation loss or accuracy | Names affected epochs; withholds trend analysis |
| `trend.generalization-gap.v1` | Training mean falls by at least max(0.02,10% of initial training mean), validation mean rises by at least max(0.02,10% of initial validation mean), and validation−training gap increases by at least 0.05 | **Possible** overfitting pattern; also compatible with data shift/evaluation differences. Suggest controlled comparisons and verified split |
| `trend.loss-growth.v1` | Either train or validation mean at least doubles using max(initial mean,0.01) baseline, and grows by at least 0.5 absolute | Sharp observed loss growth. Gradient norms are not measured, so it never claims exploding gradients |
| `error.device.v1` | Known device/backend terms: MPS, CUDA, backend, device unavailable, unsupported device, requested device | Inspect named operation and supported compute settings; no automatic fallback |
| `error.shape.v1` | Known shape/connection terms including shape, size mismatch, receives/expects, width, dimension, input port, connection, cycle | Compare incoming tensors against component contracts and repair the named dimensions/wires |
| `error.data.v1` | Known source terms including CSV, column, source, mapping, dataset, target must, observations | Inspect source preview, selected columns and cited rows; no silent record dropping |
| `error.worker.v1` | Any nonblank error not matched above | Preserve raw error and acknowledge this rule set cannot identify a specific cause |

Error classification precedence is device, shape, data, generic. Matching is case-insensitive; evidence preserves the exact original error including case and whitespace. Classification is navigation assistance, not a replacement for the runtime message. Empty/whitespace errors produce no finding. No rule suggests a generic Softmax insertion or modifies model behavior.

## Expansion boundary

Future rules should add a versioned ID, required measurement contract, disclosed threshold, negative controls, known confounders and a proposed next experiment. Gradient, activation, saturation, imbalance, leakage and hardware-memory diagnoses need their own measured signals before making specific claims. Changes to this initial rule set need new version/evidence records; a larger diagnostic catalog is future work.

## Step26 additive registry and report contract · 2026-10-05

The seven existing rule IDs now belong to the reviewed `DiagnosticRuleRegistry.builtIn`: schema1, ID `kwip.run-diagnostics`, version1. Each rule has an evaluator discriminator, rule version1, title, suggestion, prerequisites, numeric thresholds or lexical terms, confounders, and missing-evidence policy. Thresholds and matching terms are the actual evaluation inputs. Registry validation accepts only this exact supported definition; unknown versions, duplicate or changed rules, and threshold drift are rejected. Registry JSON is metadata, not executable plugin code. Device advice now points to **Project settings**, matching current navigation.

`RunDiagnostics.evaluate(_:error:)` remains compatible with the existing finding UI. `RunDiagnostics.report(_:error:context:registry:)` is the throwing detailed API. It returns `DiagnosticReport` schema1 with the registry pin, input hash, caller context, observation count, findings, all seven evaluation dispositions, and explicit limitations. `RunDiagnostic` retains `id`, `title`, `evidence`, and `suggestion`, adding schema1 and provenance. Its four-field initializer remains available for source compatibility, but such a finding has no verified report provenance and fails detailed report validation until provenance is supplied.

`DiagnosticInputContext` accepts an optional bounded run reference and a sampling declaration (`unspecified`, `complete`, or `sampled`). These are caller assertions, not independently discovered facts. No run identity is inferred from a file path. The SHA256 binds schema1 input serialization: ordered observations with exact Double bit-pattern strings, optional raw error, and context. This permits deterministic fingerprints of NaN/infinity without nonstandard JSON numbers. It binds the provided local input snapshot, **not authenticity, source trust, or a security guarantee**; it does not establish unchanged train/validation partitions or evaluation conditions.

Finding provenance includes the registry and rule versions, matching input hash/context, input observation count, zero-based source indices with epoch numbers, whether raw error was used, and named finite derived signals. Trend findings reference the selected latest positive distinct epochs, including the source index of the last duplicate. Non-finite findings reference the first eight affected observations while separately retaining the full affected count. Error findings reference the raw error and preserve its exact text, including whitespace/case; errors are not silently truncated or reworded. These local reports are not a redacted sharing/export feature: raw errors can contain private paths. A future export must apply an explicit redaction policy rather than pretending this local schema is already suitable for sharing.

Measurement collection, derived window statistics, evaluation, and presentation are separate. Report evaluation states are `emitted`, `notTriggered`, and `withheld`. Reasons distinguish absent error/metrics, earlier lexical classifier, insufficient distinct observations, non-finite measurements, invalid metric domains, and non-finite derived arithmetic. Derived overflow now explicitly withholds trends instead of producing an unserializable infinite gap. Healthy-looking inputs yield `notTriggered`, never an assertion of model health. Error classification remains navigation assistance; trend thresholds remain **uncalibrated heuristics**. No gradients, activations, hardware memory, leakage, or other unavailable measurements are inferred.

`DiagnosticRuleRegistry.decode` and `DiagnosticReport.decode` are the validated JSON entry points (8 MB input bound). They reject unsupported schemas/version pins and unknown document fields. Report validation also rejects contradictory rule status/reason pairs, missing or mismatched finding provenance, duplicate/out-of-range references, undeclared signal names, inappropriate raw-error claims, non-finite derived values, and inconsistent gap arithmetic. It is structural/version validation, not re-execution against an authenticated source. Native presentation should consume report dispositions and registry declarations rather than reproduce thresholds in view code.

## Durable terminal snapshots — local schema1

This supersedes candidate37's “not yet saved automatically” limitation. New terminal experiment records save an independent immutable diagnostic archive before the history index is published; worker manifests remain untouched. `ExperimentRecord.diagnosticReport` holds a schema1 SHA256 reference, or `diagnosticError` explains why original evidence could not be saved. `WorkspaceStore.loadExperimentDiagnostics(_:)` returns `.legacy` only when neither field exists, `.verified(DiagnosticReport)` for verified originals, or `.unavailable(String)` for missing, incompatible or invalid evidence. The Experiments disclosure uses this API; Run's current rule evaluation remains a separate reevaluation.

The path is derived solely from validated project/experiment UUIDs: `diagnostic-reports/<project>/<experiment>.json`. The archive binds terminal status, the experiment record digest (excluding diagnostic fields), exact ordered Double bit-pattern observations, exact raw error, complete pinned rule registry, and original report. Chart observations are retained as supplied; a distinct latest received metric is appended without interpolation. Sampling is `sampled` when observed gaps or an initial epoch above one establish omissions, otherwise `unspecified`. Non-finite summary values become absent history summary fields while their original bits remain in diagnostic observations.

Completed reports additionally require a bounded schema1 completed manifest with the matching graph under `runs/<UUID>/artifacts/manifest.json`, and pin its exact bytes. Interrupted records retain their own failed/cancelled identity without pretending a completed manifest exists. Loading verifies all pins/identities and replays the original observations with the supported pinned registry; it returns the stored report only when replay matches. Unsupported future/historical rule implementations are unavailable until explicitly supported, never silently recomputed with current rules.

Reads open the explicitly trusted workspace root and traverse descendant directories and files descriptor-relatively with no-follow checks. Artifact reads require regular files, bounded descriptor reads and stable size/mtime. Writes create exclusive temporary files, fsync and atomically link without replacing an existing archive. Both archive bytes (8 MB) and observations (100,000) are bounded. A failed archive save still records the experiment with an unavailable reason; unreadable or oversized history preserves its prior bytes. An index failure can leave an unreferenced archive, never a fabricated successful index write. Local hashes support consistency/replay, not authenticity against an actor who can rewrite all local records and artifacts. These archives can contain private raw errors and are not a redacted export.
